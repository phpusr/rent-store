# Обновление RentStore с Angular 14 до Angular 22

Цель — обновить приложение до последней стабильной версии Angular 22. На 20 ноября 2026 года тег `latest` для `@angular/core` указывает на **22.3.0**. Перед миграцией сверить актуальные стабильные версии Core, CLI и Material и зафиксировать совместимый набор в `package-lock.json`. Сохранить работу веб-версии и Electron, русскую локализацию и совместимость с существующими данными. [Релизы Angular](https://angular.dev/reference/releases), [версии @angular/core в npm](https://www.npmjs.com/package/%40angular/core?activeTab=versions).

## 1. Зафиксировать исходное состояние

- Начать в отдельной ветке с чистым рабочим деревом. На Node.js 16.20.x выполнить `npm ci`, `npm run build` и `npm test -- --watch=false --browsers=ChromeHeadless`. При необходимости указать Chromium через `CHROME_BIN`. Записать число тестов и уже существующие ошибки.
- На тестовом профиле сохранить JSON-экспорт с несколькими квартирами и показаниями за разные годы. Сохранить снимки таблицы, статистики и диалогов в обеих темах, включая узкое окно.
- Зафиксировать, как запускается установленная версия Electron и где она хранит профиль. Для проверки обновления использовать копию профиля, чтобы сравнить данные до и после запуска.

## 2. Обновлять Angular на одну основную версию за шаг

На каждом переходе заменить `N` в командах номером следующей версии, выполнить миграции и просмотреть их diff. Обычно сначала обновляются CLI и Core, затем Material, который подтягивает совместимый CDK.

```sh
npx ng update "@angular/cli@^N" "@angular/core@^N"
npx ng update "@angular/material@^N"
```

Если peer dependencies старого Material препятствуют первому вызову, передать CLI, Core и Material вместе в один `ng update` для того же `N`. При конфликте сверить диапазоны всех пакетов Angular, включая `@angular/localize`, а также TypeScript и `zone.js`. Если временный CLI выбирает версию, несовместимую с текущим Node.js, запустить CLI целевой версии через `NG_DISABLE_VERSION_CHECK=true npx --yes --package="@angular/cli@N" ng update …`. RxJS 7.5 входит в поддерживаемый Angular 22 диапазон.

После каждого перехода выполнить чистую установку, production-сборку и headless-тесты. Проверить запуск приложения с русской локалью и сохранить рабочий шаг отдельным коммитом с манифестом и lock-файлом. [Матрица совместимости](https://angular.dev/reference/versions), [Angular Update Guide](https://angular.dev/update-guide), [команда ng update](https://angular.dev/cli/update).

## 3. Адаптировать темы, сборку и Electron

- **Material.** Проверить `src/theme.scss`, локальные mixin-файлы тёмной темы и селекторы старой разметки, в частности `.mat-header-cell`, `.mat-form-field` и `.mat-dialog-actions`. По возможности привязать стили к собственным классам или публичным API Material. Для обеих тем проверить цвета, сортировку, плотность таблиц, фокус и размещение кнопок в диалогах. [Руководство по MDC](https://v17.material.angular.dev/guide/mdc-migration).
- **Сборка.** Переход на `application` выполнен на Angular 18. Веб-сборка создаётся в `dist/rent-store/browser`. `make build` передаёт относительный `base href` в Angular CLI и копирует файлы Electron в корень `dist/rent-store`. Electron открывает `browser/index.html`. Arch-рецепт копирует весь каталог рекурсивно. Проверены веб-сборка, русский интерфейс через Vite, оба способа запуска Electron и все 13 тестов Jasmine/Karma. При следующих обновлениях CLI сохранять Jasmine/Karma и сверять число тестов. [Миграция сборщика Angular](https://angular.dev/tools/cli/build-system-migration), [Karma и Jasmine](https://angular.dev/guide/testing/karma).
- **Локализация.** Сохранить `ru-RU` в конфигурации разработки и текущую локаль production-сборки. Прогнать `npm run i18n`, проверить diff в `src/locale/messages.xlf` и при изменении идентификаторов перенести переводы в `src/locale/messages.ru.xlf`. Проверить русскую сборку и строки из шаблонов и `$localize` в интерфейсе.
- **Electron.** В `electron-src/package.json` указан Electron 22, а Arch-пакет запускает Electron 30. Выбрать поддерживаемую стабильную ветку с Chromium, соответствующим требованиям Angular 22, и согласовать её между `electron-src/package.json`, его lock-файлом, `package/PKGBUILD` и `package/rent_store.sh`. Проверить `make build`, относительный `base href`, загрузку JS/CSS через `file://`, навигацию и повторный запуск с копией прежнего профиля. Локальную проверку пакета выполнить без вызова `make mk_package`, поскольку эта цель делает `git push` и устанавливает пакет. [Поддерживаемые браузеры Angular](https://angular.dev/reference/versions#browser-support), [график релизов Electron](https://releases.electronjs.org/schedule).

## 4. Проверить готовность

- Чистый `npm ci` на итоговом Node.js, production-сборка, headless-тесты и сборка Electron проходят. В браузере и Electron работают переходы между годами, диалогами, статистикой и списком квартир.
- Создание, изменение и удаление квартиры и показаний корректно обновляют таблицы, итоги и статистику. Выбор квартиры, год и тема восстанавливаются после перезапуска.
- Старый JSON-экспорт и пример из `scripts/export_from_gsheets.mjs` импортируются. Новый экспорт повторно импортируется без потери данных. Ключи `localStorage` и формат расчётов по квартире, году и месяцу сохраняются.
- При регрессии вернуться к последнему проверенному коммиту вместе с соответствующим lock-файлом и версией Node.js. Для повторной проверки Electron использовать сохранённую копию профиля.
